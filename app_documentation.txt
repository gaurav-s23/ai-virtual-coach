SECTION D — SYSTEM FLOW (STEP-BY-STEP)
--------------------------------------------------------------------------------

D.1 RAG flow (resume indexing and retrieval)
--------------------------------------------
  1. Client sends POST /api/start-interview with multipart PDF + form fields (jd, role,
     user_id).
  2. main.py validates file size/type; sanitize_filename; reads bytes.
  3. rag.store.upsert_resume writes PDF to temp path; PyPDFLoader loads documents.
  4. Metadata (user_id, source, filename) attached; RecursiveCharacterTextSplitter
     produces chunks (1000 chars, 150 overlap).
  5. HuggingFaceEmbeddings (CPU, normalized) embed each chunk; Chroma collection
     user_{user_id}_docs persists vectors under CHROMA_DIR.
  6. Extracted plain text (preview) feeds ai_engine.generate_initial_interview for
     intro + questions (LLM JSON).
  7. session_manager creates in-memory agent session; SQLAlchemy Interview row inserted
     with new session_id.
  8. Later, during POST /api/interview/chat, the agent may invoke ResumeSearch tool,
     which calls rag.store.retrieve(user_id, query, k) → similarity_search in Chroma
     and returns top text chunks to the LLM.

D.2 Authentication flow (signup, login, JWT access, refresh rotation)
--------------------------------------------------------------------
  1. Signup: POST /api/auth/signup with email/password → password validated and hashed
     with Argon2 → new User row; returns id/email/name (no tokens in this handler).
  2. Login: POST /api/auth/login → lookup User by email → verify_password against
     stored hash (Argon2 or legacy bcrypt) → issue_token_pair.
  3. issue_token_pair: create_access_token (JWT: sub=user id, type=access, exp) +
     generate opaque refresh token → SHA-256 hash stored in refresh_tokens with
     expires_at; commit → return access_token, refresh_token, expires_in to client.
  4. Protected API: Client sends Authorization: Bearer <access_jwt>; OAuth2PasswordBearer
     extracts token; jwt.decode with JWT_SECRET_KEY; require type=access; load User;
     inject request.state.user_id for rate limiting.
  5. Access expiry: Client calls POST /api/auth/refresh with JSON { refresh_token }.
  6. auth_refresh: hash body token; find RefreshToken row by token_hash; verify user;
     rotate_refresh_token marks old row revoked (revoked_at), issues new pair via
     issue_token_pair (new refresh hash row).
  7. Legacy POST /api/login: same user lookup or auto-register; returns token fields
     compatible with older clients storing `token` or access_token.

SECTION E — TECHNICAL STACK SUMMARY (WHY EACH TOOL)
--------------------------------------------------------------------------------

Frontend — React + Vite
  Industry-standard component model and fast HMR/builds; Vite keeps iteration quick
  and outputs static assets ideal for Nginx hosting.

React Router
  Client-side routing for a multi-page feel without server round-trips; supports
  protected routes for authenticated flows.

Tailwind CSS
  Rapid, consistent UI with utility classes; pairs well with design iteration for
  dashboards and interview UIs.

Axios
  Mature HTTP client for JSON, interceptors, and straightforward Bearer header usage
  from the browser.

Nginx (in Docker)
  Serves the SPA, handles client-side route fallback, and reverse-proxies /api to
  FastAPI—enabling same-origin API calls and simpler CORS in production.

Backend — FastAPI
  Async-capable API framework with automatic OpenAPI docs, Pydantic validation, and
  clean dependency injection for DB sessions and auth.

SQLAlchemy + Alembic
  Portable ORM for Postgres/SQLite and versioned schema migrations—required for
  production data integrity and refresh-token storage.

PostgreSQL (Compose)
  Robust relational DB for concurrent access, JSON/JSONB for transcripts, and indexed
  lookups on session_id and token_hash.

ChromaDB
  Embedded vector store with filesystem persistence—no separate vector DB service for
  development and small deployments.

sentence-transformers / HuggingFace
  Local CPU embeddings avoid per-token embedding API costs and keep resume text
  processing on-premise within the backend container.

LangChain (agents, memory, Chroma integration)
  Standard abstractions for tool-calling agents, conversation memory, and vector
  store adapters—reduces glue code between retrieval and Gemini.

LiteLLM
  Single interface to multiple model providers with a configurable fallback chain—
  resilience when Gemini is rate-limited or unavailable.

Google Gemini (via GOOGLE_API_KEY)
  Strong general-purpose LLM for JSON interview tasks and agent replies; chosen as
  primary cloud model in env and README.

PyPDF / LangChain loaders
  Reliable PDF text extraction path for resumes before chunking.

JWT (python-jose) + opaque refresh tokens
  Stateless short-lived access tokens for APIs; server-side revocable refresh tokens
  stored hashed—balances performance and security.

Argon2 (passlib)
  Modern password hashing default with backward compatibility for bcrypt hashes.

SlowAPI
  Optional rate limiting to protect auth and expensive endpoints from abuse.
